### Entity Type Fill Colors (5 required — D-04)

These are the primary visual channel for node identity. Colors are chosen for:
1. Perceptual distinctness at WebGL rendering sizes (8–16px radius nodes)
2. Sufficient contrast against both `#ffffff` (light) and `#0a0a0a` (dark) backgrounds
3. Alignment with the existing brand palette (teal primary `#0f766e` / `#2dd4bf`)

| entityType | Light Mode Hex | Dark Mode Hex  | Description                  |
|------------|----------------|----------------|------------------------------|
| Person     | `#2563eb`      | `#3b82f6`      | Blue — individual actors     |
| Org        | `#0f766e`      | `#2dd4bf`      | Teal — brand primary, institutions |
| Concept    | `#7c3aed`      | `#a78bfa`      | Violet — abstract ideas      |
| Event      | `#d97706`      | `#fbbf24`      | Amber — time-bound occurrences |
| Claim      | `#e11d48`      | `#fb7185`      | Rose — assertions/claims     |

Fallback (unknown/missing `entityType`): `#64748b` (slate-500) — neutral gray.

**Rationale:** Person=blue and Org=teal align with the existing `nodeColor()` function's blue (`#2563eb` for `aesthetic`) and teal (`#0f766e` for `brand`). Concept=violet was already used for `query` category. Claim=rose aligns with the existing `competitor` category red (`#e11d48`). Event=amber is new — distinct from all existing colors. This continuity minimizes visual regression for users familiar with the current graph.

**Source:** Existing `nodeColor()` in `app/tool/page.tsx` lines 609–615; adapted and extended for the 5-type schema.

### Louvain Community Ring Colors (8-slot palette — D-05, D-06)

Community rings render only when Louvain detects ≥3 communities. Ring thickness: 15% of node radius via `createNodeBorderProgram` factory.

| Slot | Hex       | Notes                         |
|------|-----------|-------------------------------|
| 0    | `#f97316` | Orange — warm, distinct from entity types |
| 1    | `#06b6d4` | Cyan — cool contrast          |
| 2    | `#84cc16` | Lime — bright-mid             |
| 3    | `#ec4899` | Pink — warm-mid               |
| 4    | `#14b8a6` | Teal-light (brand-accent)     |
| 5    | `#f59e0b` | Amber-warm                    |
| 6    | `#8b5cf6` | Purple-mid                    |
| 7    | `#6366f1` | Indigo                        |

When ring is hidden (`count < 3`): `borderColor: 'transparent'` on all nodes.

**Source:** Claude's Discretion (CONTEXT.md); palette selected for perceptual distinctness and WCAG AA contrast at small node sizes.

### Edge Colors (relType encoding — D-07)

Sigma v3 has no native dashed edges. Encoding uses size + color/opacity differentiation.

| relType / condition  | Stroke Color                  | Stroke Width | Notes                               |
|----------------------|-------------------------------|--------------|-------------------------------------|
| `causal`             | `#94a3b8` (slate-400)         | 3.5px        | Solid, thick — strong relationship  |
| `associative`        | `#64748b` (slate-500)         | 1.5px        | Solid, medium — standard link       |
| `contextual`         | `rgba(100,116,139,0.35)`      | 1px          | Muted/transparent — weak/ambient    |
| `missing: true`      | `#fb7185` (rose-400)          | 2px          | Existing gap edge treatment; preserved |
| Selected edge        | `#94a3b8` at full opacity     | 4px          | Existing selection-weight pattern   |
| Unknown relType      | `rgba(100,116,139,0.35)`      | 1px          | Fallback to contextual treatment    |

**Source:** RESEARCH.md Pattern 7 (verified against sigma v3 constraints); existing `app/tool/page.tsx` edge stroke colors (`#fb7185` for missing, `#64748b` for standard).

### Node Selection

Selected node: `borderColor: '#f8fafc'` (slate-50 / near-white) at full opacity — creates a bright halo that reads against both light and dark backgrounds.

Non-selected node: `borderColor` = community ring color (if rings active) or `'transparent'` (rings inactive).

**Source:** Existing SVG `stroke={isSelected ? "#f8fafc" : "transparent"}` in `app/tool/page.tsx` line 1390; adapted for sigma `borderColor` attribute.

## Copywriting Contract

Phase 6 has minimal copy changes. The graph renderer is a visual component; copy lives in the surrounding parent page.

| Element                     | Copy                                                           |
|-----------------------------|----------------------------------------------------------------|
| Graph container toolbar (existing, preserved) | "Export PNG" button label (existing; button becomes non-functional placeholder until Phase 7 implements canvas export — see D-17) |
| Loading state (sigma init)  | No text — pulse skeleton only                                  |
| Empty graph state           | "Run an analysis to generate the semantic network." (existing empty state copy in parent page — preserved, no change) |
| Gap node hint label         | `node.gapHint` value from synthesis — preserved as-is via sigma label rendering |
| Error state (sigma/worker)  | Console only — `[semantic-graph] sigma initialization failed` / `[semantic-graph] FA2 worker failed` — no user-visible error copy in Phase 6 |
| Louvain ring label          | No label — visual only, no legend in Phase 6 scope            |
| Entity type legend          | No legend — visual only in Phase 6; legend deferred to Phase 7 |

**Note on Export PNG button:** The existing button calls `exportGraphPng()` which targets the SVG element. When the SVG block is replaced by `<SemanticGraph>`, this handler will no longer work. The button should be hidden or disabled in Phase 6 (not removed, to avoid layout shift) and re-enabled in Phase 7 when `canvas.toBlob()` export is implemented. Suggested: `disabled` + `opacity-50 cursor-not-allowed` classes.

**Source:** D-17 (PNG export deferred to Phase 7); existing `app/tool/page.tsx` empty state copy pattern.

## ForceAtlas2 Configuration Contract

These values are part of the visual contract — they determine how the graph looks when it stabilizes.

| Parameter           | Value   | Rationale                                              |
|---------------------|---------|--------------------------------------------------------|
| `slowDown`          | 10      | Smooth convergence; prevents oscillation               |
| `gravity`           | 1       | Keeps disconnected nodes from flying off-screen        |
| `scalingRatio`      | 2       | Moderate spacing — not too compressed, not too sparse  |
| `barnesHutOptimize` | `true`  | Required for 200+ node performance (VIS-01)            |
| `barnesHutTheta`    | 0.5     | Standard approximation quality/speed trade-off         |
| Auto-stop timeout   | 6000ms  | Sufficient for medium graphs (50–150 nodes); acceptable for 200+ |

**Source:** RESEARCH.md Pattern 3 (verified parameters).

## Accessibility

- Node labels rendered via sigma WebGL canvas text — not DOM elements. Screen reader access to graph content is not provided by sigma. This is a known limitation of WebGL graph renderers; no regression from current SVG approach (which also does not expose semantic graph structure to screen readers).
- Keyboard navigation of the graph: not in Phase 6 scope (sigma does not provide native keyboard node traversal).
- Color-only encoding: entity type colors are the primary channel. Users with color vision deficiencies cannot distinguish entity types by color alone. Node label text provides a secondary channel. A shape-based secondary encoding (different node sizes by entity type or `entityType` displayed in label) is a Phase 7 accessibility concern.
- Reduced motion: `prefers-reduced-motion` media query already in `app/globals.css` (`animation-duration: 0.01ms`). ForceAtlas2 worker animation does not use CSS animations — it updates node positions directly. The worker should auto-stop immediately (timeout = 1ms) when `prefers-reduced-motion: reduce` is active. Implementation detail for the executor.
